# 🛠️ Как использовать папку «Приложения_Библиотека_Технологий» — MVP-логика v6.0

Этот файл дополняет основной README и содержит практическую инструкцию для эксперта, команды пилота, инвестора и юриста.

## Базовый принцип

Приложения используются не как «энциклопедия будущего», а как **операционный пакет пилота**.

1. Определить, что входит в **нулевое ядро (Node Zero)**.
2. Разложить решения по **уровням готовности (PTRL)**.
3. Назначить обязательные доказательства по **матрице доказательств (Evidence Matrix)**.
4. Подготовить **MVP-право** и **протокол резидента (resident protocol)**.
5. Только после этого подключать сложные AI/ESG/масштабные опции.

## Для эксперта

- Откройте нужный раздел (строительство/энергетика/агротехнологии).
- Сверьте допущения с `ИСТОЧНИКИ_И_БЕНЧМАРКИ.md` и KPI в основном ТЭО.
- Проверьте наличие "паспорта интеграции" у каждой технологии (в ПОДРОБНО файле).
- Проверьте, относится ли решение к пилоту или к опции следующей стадии.

## Для пилота (MVP)

Рекомендованный минимальный пакет для запуска пилота:

- `Шаблоны_документов.md`: договоры пилота, resident protocol, data policy, шаблон Evidence Matrix.
- `Каталог_инновационных_решений.md`: выбрать только PTRL-1 и PTRL-2 решения для Node Zero и пилота.
- `Примеры_бизнес_процессов.md`: адаптировать процессы отбора, онбординга, доступа к Ядру, инцидентов и биллинга.
- `Нормативные_акты_и_стандарты.md`: проверить обязательный правовой путь пилота.
- Простая таблица мониторинга KPI и фактов (см. `Шаблоны_документов_ПОДРОБНО.md`, если понадобится расширенная версия).

## Минимум Node Zero

Нулевое ядро (Node Zero) считается собранным, если в приложениях зафиксированы и подтверждены:

- модуль или ангар Ядра;
- связь и резервный канал;
- электропитание, ИБП и резерв;
- MQTT/API/data stack;
- helpdesk и базовое resident app;
- паспорта объекта, оборудования и инцидентов;
- регламент доступа, privacy policy и журнал ролей.

## Матрица доказательств (Evidence Matrix): что должно быть на руках

| Блок | Минимальное доказательство |
| :--- | :--- |
| Земля и инженерия | shortlist участка, ограничения, предварительные ТУ |
| Технологии | КП, спецификации, схема подключения, owner |
| Экономика | CAPEX/OPEX sheet, тарифы, сценарий загрузки |
| Право | договоры v1, устав, политика данных, регламент доступа |
| Коммерция | LoI, резервы, анкеты резидентов, продуктовые пакеты |
| Эксплуатация | SOP, аварийный протокол, KPI dashboard |

## Мониторинг и верификация (кратко)

- Для каждого KPI укажите: метод измерения, частоту, ответственного, инструмент (сенсор/лаборатория/BI).
- Формат обмена данных: CSV/JSON или API; при отсутствии — укажите ручной протокол съёма данных.
- Рекомендуемый минимум: 5 ключевых KPI для пилота (заполняемость, доход на семью, энергозависимость, вода на семью, прирост гумуса).

## Resident Protocol: минимум для запуска

До запуска пилота должны быть определены:

1. анкета кандидата и критерии пре-квалификации;
2. интервью и background-check;
3. тест-драйв или буткемп;
4. правила подключения к Ядру и пользования сервисами общего контура;
5. офбординг, медиация, условия выхода и переуступки.

## Процесс обновления

- Обновляйте подробные файлы (`*_ПОДРОБНО.md`) — краткие сводки обновляются автоматически из них.
- Вносите изменения с пометкой: `YYYY-MM-DD — Источник — Причина`.
